# Changelog

All notable changes to this project are documented here.

## [Unreleased]

- **The window writes the same program as the command:** it now has the lead-in and lead-out (0.3 mm by default, also by shape of the opening), the wait of the laser, the passes, the origin and the bed among its parameters, with the limits of the command line, and leaves out an opening repeated in the same place. Before, the window wrote no leads, no wait, one pass and had no bed limit.
- **The bed limit counts the lead-ins and the lead-outs:** `--bed` (and the bed of the window) refuses G-code whose lead-in starts or lead-out ends outside the bed, not only a point of a contour. A stencil moved to `--origin 0,0` needs room for its leads. A HP-GL plot has no leads and is checked as before.
- **The window asks before it removes a signature:** saving into a project that is signed, or whose branch `stencilcam/` is, shows what would be removed and writes nothing until it is agreed.
- 6 new tests.
- **The stencil of one side no longer takes the place of the other:** the paste layers `board.gtp` and `board.gbp` were both kept as `stencil-board.nc`, so the bottom side silently replaced the top one. When two layers would share a name, each is now kept with its whole name (`stencil+board.gtp.nc`). A file name that two layers share is no longer chosen by guess with `--layer`: the path says which.
- **Nothing is written over a project or over a file the run reads:** `convert` and the window refuse an output that ends in `.eh3d`, and `convert` one that is the settings file, the table of tools or the table of sheets.
- **The window says when keeping a stencil removed a signature** of the project.
- 4 new tests with invented projects.

## [0.1.3] - Makes stencils straight from the shared project of the suite

- **The reading and writing of the job of an `.eh3d` project are shared:** they are the module `eh3d_project::manufacturing` of EH3D-COMMON, the same for every manufacturing program; the commands, the window and the files of a project do not change.
- **The project of the suite (`.eh3d`):** `project info FILE` shows the layers of the job (the branch `manufacturing/`, a `.eh3dproj` package) and the stencils kept in the project, and `project convert FILE` turns each paste layer of the job (or the one named with `--layer`) into a stencil kept in the branch `stencilcam/` only, with a copy of the layer and a reference to the content of the job. A job that changes afterwards makes the stencils out of date (exit 2). 7 new tests with invented projects.
- **A list of sheets and the layer of the job in the window:** a table of sheets (`.csv`, dropped or opened with its button) offers its sheets in a list, a dropped `.eh3d` file opens the paste layers of its job (top and bottom are chosen from a list) and the stencil can be saved back to the project. The words are in the eight languages; no person has looked at the window yet.
- The crate `eh3d-project` of EH3D-COMMON is now used; Rust 1.89 or newer is needed.
- **A path with no point no longer stops the order of the cuts, and an artifact cannot be named `.` or `..`:** `ordered_indices` read the first point of every path and panicked on an empty one, so the program, the plot and the time of a list with an empty path all stopped (an empty path is now left out); the name of a file kept on the server could be `..` or hold a character that reverses or hides text. 33 new tests cover the order of many paths, the leads, the times, the plot, the atomic write and the server names and bytes.
- The shared workflow checker (`tools/workflow_hygiene.py`) is the current one of the documentation hub: the filters under a trigger (branches, paths, types) are no longer read as events.
- **Built against the released shared library:** the workflows take the tag v0.3.3 of EH3D-COMMON instead of its main branch; EH3D-GERBERVIEWER is taken at the tag v0.1.0.

## [0.1.2] - Sheets from the tool crib and DXF output

- **A sheet of the tool crib sets the stencil:** `--sheet-file SHEETS.csv --sheet NAME` takes a sheet from the table of sheets that the tool crib exports (`export-sheets-csv`): its thickness, its reduction of every opening on each side, its kerf and its two ratio limits replace those of the material. A kerf of 0 in the sheet takes the beam width of the laser given with `--crib` and `--crib-laser` (or `--kerf`), and a ratio limit of 0 gives none. The thickness and the reduction are not given twice (`--thickness` and `--shrink` are refused with a sheet), nor is the kerf when the sheet has one; `--min-aspect` and `--min-area` win over the sheet, and the sheet over the settings file. No figure of a sheet is a default of this program.
- **The table of sheets is read with the same care as the kerf:** the columns are found by their names, in any order; a file over 1 MiB or a table of more than 10,000 rows is refused; a missing column, a repeated name (in any case), a kind that is not `sheet`, a figure that is not a number or is out of its range is an error that names its row; the protection against formulas that the crib adds is taken off; and a fuzz with a fixed seed shows that a damaged table never panics.
- **The settings file can choose the sheet:** `sheet_file` and `sheet_name` in `stencil.cfg` do the same as the two options, which win over the file; `eh3d-stencilcam config` lists them as comments.
- **A reduction of every opening, in millimetres on each side:** besides the percent of the material, the profile has a reduction in millimetres that the sheet gives; an opening that it would leave with no size is an error.
- **The window shows the sheet that was chosen:** the side panel says its name, thickness, reduction and kerf in the eight languages, and the window takes the ratio limits of the sheet to say which openings will not release the paste.
- **The openings can be written as a drawing:** `convert LAYER OUT.dxf` writes the openings as the stencil has them (after the reduction, before the kerf), circles and rectangles in millimetres, in a text that is the same each time and that the reader of drawings of this program reads back as the same openings. An obround opening is refused unless `--force` leaves it out, and a file that exists is never replaced unless `--overwrite` is given (`--create`, the default, refuses it).

## [0.1.1] - Openings from straight tracks, rectangle regions and macro pads, the limits of the ratios as settings, the kerf read from the tool crib and the code 2 for a check that does not pass

- **The pictures of the README are new:** they were written again by the picture mode (`--shot`) of the published program.
- **Requirements with identifiers and tests that name them:** `docs/REQUIREMENTS.md` is the register of what the program must do, one row for each capability with an identifier (`STNC-001` on), its state (planned, prototype, implemented or validated), how far it is (done, partial, pending or blocked), its evidence and the test that shows it; a capability that is not written names the test that will show it. `tests/reqs.rs` reads the table and fails when a test does not exist, when a state does not agree with the progress or the evidence, when `docs/STATUS.md` does not say the same numbers, when a README does not link the documents or when a document holds a date or a private reference. The five documents of the family (`docs/SCOPE.md`, `docs/REQUIREMENTS.md`, `docs/STATUS.md`, `docs/NOT_YET.md` and `AGENTS.md`) are in the repository and are linked from the eight READMEs.
- **Tracks along an axis, rectangles drawn as regions and macro pads that are rectangles become openings:** a track with a round pen along X or Y is an obround opening (a round one when it is a point), a region that is a rectangle and a macro pad made of one are rectangular openings; a track at an angle and a region of another shape are notes that say which one and why, the first five written one by one and the rest counted. `convert` still refuses a layer with such notes unless `--force` is given.
- **A pad with cut corners can be opened as its rectangle:** `region_fit_percent` in `stencil.cfg` and `--region-fit PERCENT` (0 to 20, 0 by default) open a region that fills at least 100 minus that percent of its enclosing rectangle, such as a pad with rounded or cut corners, as that rectangle, and say how many were changed; with 0 only an exact rectangle is an opening.
- **The ratio limits are settings:** `min_aspect` (0.5 to 10, 1.5 by default) and `min_area` (0.1 to 2, 0.66 by default) in `stencil.cfg` and `--min-aspect` and `--min-area` on the command line replace the fixed limits; a value out of its range is an error that says its line, and `eh3d-stencilcam config` prints them.
- **Each opening that will not release the paste says what would fix it:** the reason names the ratio, its limit and the thickest sheet for which that opening would meet both limits; the number is the same one the tests check on seeded random openings.
- **A check that did not pass ends with the code 2:** `check`, `check --json` and `convert` return 2 when an opening will not release the paste or the layer cannot all become openings, and 1 for a mistake in what was asked or a file that cannot be read or written, so that a script can tell them apart; the help lists the codes.
- **The kerf can come from the tool crib:** `--crib FILE.csv --crib-laser NAME` takes the kerf from the beam width of a laser tool in the CSV that the tool crib of the suite exports; the table is read with a size limit (1 MiB) and a row limit, every fault names its row, a name is found in any case, and giving `--kerf` as well is an error. The tests feed it damaged tables with a fixed seed.
- **The window shows the ratios:** the side panel lists the smallest aspect and area ratios and those of the five weakest openings, in the eight languages.

## [0.1.0] - Send stencils to the EH3D server and a server status command

- **A server mode over the client of the suite:** `stencil.cfg` takes the keys `server_address`, `server_token`, `server_machine`, `server_timeout_s` (1 to 120, 15 by default), `server_retries` (0 to 5, 2 by default), `server_mdns` (`off` by default) and `server_max_answer_mib` (1 to 256, 8 by default), read with their ranges by `eh3d-serverclient` of EH3D-COMMON; a value out of its range, a key given twice or a space in the address is an error that says its line; the mode is off until `server_address` is set and the local work never depends on it.
- **`eh3d-stencilcam server status`:** shows the link (the token as `***`) and what the server answers at `/health`, with the refusals and the failures of the network told by their code in the language of the system (taken from `LC_ALL`, `LC_MESSAGES` or `LANG`).
- **`convert --to-server` keeps the stencil on the server:** the G-code or the HP-GL plot that `convert` writes is kept on the EH3D server as an artifact once it is written locally (one request, never repeated by the client); the option is refused before any work when `--config` has no `server_address` or `server_token`, and a refusal of the server is told after the local file was written.
- **`check --json --to-server` keeps the result of the check:** the JSON object that `check --json` prints is kept as the artifact `LAYER.check.json`; `--to-server` is refused on any other command.
- **The artifact says what it is and how it was made:** its media type follows the file (G-code, HP-GL plot, DXF drawing, JSON, text) and its parameters carry the command, the thickness of the sheet, the shrink, the speed of the cut, the top of the laser scale, the passes and the number of openings.
- **The CI and the release build take `EH3D-COMMON` at `v0.2.5`:** the sibling that is checked out is the release that has the client of the server, and the manifest lists `EH3D-COMMON` in `depends_on`.

## [0.0.9] - Narrow web warning, repeated apertures and a JSON check

- **A warning for openings whose web is too narrow:** `--min-web MM` (or `min_web_mm` in `stencil.cfg`, from 0 to 5 mm, 0.1 by default, 0 for no warning) warns, in `check` and in `convert`, of two openings whose web (the sheet that stays between them, measured between their circles when both are round and between their enclosing rectangles otherwise) is narrower, and of openings that touch or overlap; the warning never stops `convert`. The pairs are found with a sweep along X and the tests compare it with the comparison of every pair on a pseudo-random board.
- **An opening that repeats another one is cut once:** two openings of the same form, size and place (to within a thousandth of a millimetre) are one hole, so the second is left out with a note on the standard error instead of burning the edge of the first by cutting it twice; the first of the layer keeps its place and the number of passes is not affected.
- **`check` tells the paste the openings hold:** it prints how many openings there are of each form and the paste they hold, in microlitres (the area of each opening as it is cut times the thickness of the sheet), to choose how much paste to load.
- **`check --json` prints the result as one JSON object:** the number of openings by form, the paste, the smallest ratios (`null` with no openings), the openings that will not release the paste, the narrow webs and how many repeated openings were left out, for other programs to read; the exit code is the same as without it and `--json` on `convert` is refused.
- **The CI and the release build take the shared libraries at their newest releases:** the pins of the sibling repositories in the workflows are raised to the releases the program now needs, so that the build and the binaries of a release use them.

## [0.0.8] - Origin and bed options, drawings in any DXF unit and a simulated laser

- **The README says the maturity of the manifest:** the badge and the Maturity row of the eight READMEs read functional, as the manifest does, and the check of the status lights now fails when they differ.
- **`--origin X,Y` and `--bed WIDTH,HEIGHT` place the stencil on the sheet:** `--origin` moves the lower-left corner of the openings to X,Y (a board drawn far from zero or in negative coordinates no longer travels outside the machine) and `--bed` refuses to write when a point of a contour falls outside the bed; the leads are not counted.
- **A circle whose centre cannot be read is left out, and the speed range is one:** a DXF circle with a centre written with a decimal comma, overflowing or cut short used to be placed at X=0 or Y=0 without a word; it is now left out with a note, like a polyline with an unreadable corner. The speed of the cut accepted by the settings and the command line is now the same range the generator accepts (1 to 30000 mm/min); before, a value above 30000 passed the settings and failed later with another message. Tested with unreadable centres and with 30000 and 30001.
- **A drawing in mils, microns or any other unit of the DXF table is read in its true size:** the unit of the drawing was taken as millimetres for every code except inches, feet, centimetres and metres, so a pad of 60 mil became an opening of 60 mm. The whole table (from micro-inches to hectometres) is now known, and a code that is not in it is a note, which stops `convert` unless `--force` is given. Tested with mils, microns, decimetres, the two millimetre codes and an unknown code.

- **A simulated laser (`sim`):** a twin of the controller that reads the G-code this program writes (position, laser on or off, feed, cuts with the laser off, rapid moves with the laser on), a link that loses and damages lines by chance from a seed, a sender that resends a line, makes the safe stop when it gives up and resumes the job from the start of the cut that was under way. Eight new tests (185 in all) run the job over a perfect link, over 30 seeded lossy links, and over a link that dies at every line of the job followed by the resume. It has only run on a computer: no controller or laser has read this G-code.

- **The shared validation tools are updated:** the validator also runs the workflow and lessons checks of the suite with their latest rules, including a check to run before every push.
- **The CI validation checks the workflows and the lessons of past CI failures against a baseline:** `tools/workflow_hygiene.py` and `tools/lessons_lint.py` (copies of the shared tools) run in the validation, and only findings that are not in `tools/workflow_hygiene_baseline.json` and `tools/lessons_lint_baseline.json` fail it, so what exists today stays as it is and a new one is caught. `python tools/workflow_hygiene.py --root . --detail` and `python tools/lessons_lint.py --repo .` list the findings.
- **The validation of the CI is the reusable one of the documentation hub:** the job `validate` calls `validate.yml` of EH3D-DOCS (pinned by commit) and the check of the CHANGELOG is a job of its own.
- **The pins follow the new releases:** the CI and the release build take `EH3D-COMMON` at `v0.2.1` and `EH3D-CORE-LIBS` at `v0.0.9`, and the manifest asks for `min_common` 0.2.1. The picture of the window in the README is taken again with the program of today.

## [0.0.7] - DXF input, lead-in by form and speed, passes and laser scale settings

- **Fuzz tests with a fixed seed:** every cut of the example drawing and 500 damaged copies of it, damaged layers and numbers that are huge or not numbers are read without a panic; an entity whose size or place overflows is left out with a note.

- **A drawing (DXF) as input:** a file ending in `.dxf` is read by `eh3d_stencilcam::dxf_in` (circles become round openings, closed rectangles with their sides along the axes rectangular ones, the unit of the drawing is read, any other entity is a note and `convert` refuses to write unless `--force` is given).
- **The speed, the laser scale and the passes are settings:** `feed_mm_min` (600), `smax` (1000) and `passes` (1, up to 10; all the contours are cut once before the next pass) in `stencil.cfg`, and `--feed`, `--smax` and `--passes` on the command line, which win over the file; a value out of its range is refused with the name of the option.

- A screenshot of the window in the README, taken with the published program: the example paste layer with the cutting path and the opening that will not release the paste.
- **The G-code and the HP-GL file are written through a temporary file:** the command line (`convert`) and the window write the program to a file beside the real one and rename it over the real one (`output::write_atomic`), so that a cut or a full disk leaves the old file whole and never a program that stops in the middle of a cut. A failure removes the temporary file and is reported with the code `file_unwritable` and the name of the file. Tests in `tests/atomic_write.rs` and `window.rs`.
- **Lead-in and lead-out by form of the opening:** a round opening and a rectangular one can have their own leads, with `lead_in_round_mm`, `lead_out_round_mm`, `lead_in_rect_mm` and `lead_out_rect_mm` in `stencil.cfg` or `--lead-in-round`, `--lead-out-round`, `--lead-in-rect` and `--lead-out-rect` (0 to 5 mm; the option wins over the file). A length that is not given is the general `lead_in_mm` / `lead_out_mm` (or `--lead-in` / `--lead-out`), so a configuration without the new keys writes the same program as before, and an obround opening always uses the general ones. The estimate of the time (`--rapid`) counts the lead of each form. A bad value is an error that names its key and line or its option; `examples/stencil.cfg` shows the four keys as comments and is the same file as `eh3d-stencilcam config`. In the library, `gcode_with_form_leads` and `estimate_time_with_forms` take a `FormLeads` and the form of each path (`forms`, `ordered_indices`); `gcode_with_leads` and `estimate_time` are unchanged. The rules and worked values are in `docs/leads-by-form.md`.

## [0.0.6] - Estimated time of the job, lead-in and lead-out of the cut and the picture mode

- **An estimate of the time of the job:** with `--rapid MM_MIN` (or `rapid_mm_min` in `stencil.cfg`, from 100 to 100000 mm/min, 0 by default: no estimate and the output is the one it always was) `convert` prints the estimated time of the G-code job after the file is written: the cutting at the feed (leads included), the wait after each `M3` and the moves with the laser off from the origin along the order of the cuts. The acceleration of the machine is not counted. The library has `estimate_time` and `duration_text`; the tests use rectangles worked out by hand, the range of the setting and the command line (a plotter file has no estimate). `examples/stencil.cfg` carries the new key and is the same file as `eh3d-stencilcam config`.
- **A straight lead-in and lead-out on every cut:** each contour of the G-code can be entered along a straight line tangent to its first segment and left along the prolongation of its last one (`gcode_with_leads`; 0.3 mm each by default, from 0 to 5). The laser is off while the head travels to the start of the lead-in, is switched on there (after the `--laser-wait` wait, if any) and is switched off at the end of the lead-out. The outlines are convex and counter-clockwise, so both leads lie outside the opening, on the sheet that is kept. With 0 the program is exactly the one written before, and HP-GL has no leads.
- **A settings file, `stencil.cfg`:** the strict keys `lead_in_mm`, `lead_out_mm` and `laser_wait_s` (comments with `#`; an unknown key, a key given twice or a value out of its range is an error with the number of the line), read with `--config FILE` and printed with their defaults by `eh3d-stencilcam config` (`examples/stencil.cfg`); the new options `--lead-in MM` and `--lead-out MM` and the existing `--laser-wait` win over the file.
- **A picture mode for the window:** `--shot FILE.png` (built with `--features gui`) opens the window at the size of `--size WxH` (320 to 8192, 1180x760 by default), with `--theme forge|dark|light`, `--lang CODE` and the files of `--open FILE`, waits `--wait N` frames (0 to 3600, 6 by default), saves what it drew as a PNG file and closes by itself. An existing file is never replaced unless `--replace` is given, the window keeps no settings in this mode, the exit code is 0 when the file was written, 1 when it was not (also when the picture does not come back within 600 frames) and 2 for wrong arguments, and a build without the window says so. The arguments are read by plain code with its tests.

## [0.0.5] - The window of the stencil program, a laser wait before the cut and the Windows icon

- **Binaries for every system:** `release-binaries.yml` builds the program with its window for Windows (64 and 32 bits), Linux and macOS (Apple silicon and Intel), packs each one with the licence, the readme, the icon and the examples, writes `SHA256SUMS` and a build manifest, attests their provenance, verifies the artifact as a stranger would, prepares a draft release only after the owner approves it (a dry run is the default) and opens an issue `build-failed` when anything does not finish.
- **The dependencies on the shared readers name the version that has what is used:** the G-code crate (and for ISOCAM the Excellon one) is required from 0.0.7, the version that brought the way of writing a number, the header of a program and the units given by the caller.
- **A wait after the laser is switched on:** `--laser-wait SECONDS` writes a `G4` wait after each `M3` (0 by default: none; at most 60), so that the laser is at its power before the head moves.
- **The G-code is read back in the tests:** the cuts, with and without the wait, and the file of the command line are read with the reader of the suite and walked the way the strict mode of the G-code debugger walks them; there is no warning and no cut with the laser off. The header of the command line is compared with the expected text.
- **The Windows executable carries the icon of the program:** the file shows it in the explorer and the taskbar, together with the name, the description and the version, embedded by `build.rs`; other systems are not affected.
- **A window:** built with `--features gui`, `eh3d-stencilcam` with no arguments (or with a single layer file, or `gui [LAYER]`) opens a window in the look of the other programs of the suite (amber on charcoal, the icon of the program). A paste layer is opened from the list of files of the window or dropped on it; the pads and the cutting paths are drawn with zoom (wheel) and pan (drag), and the openings that will not release the paste are in red; the material, thickness, shrink, corner radius, kerf, feed and laser power can be edited; the stencil of the bottom side can be mirrored; a box allows writing although there are problems; and the stencil is exported as laser G-code or HP-GL by the name of the file. The command line works as before, and a build without the feature is only a command line.
- **The window speaks the eight languages:** English, Spanish, German, French, Italian, Japanese, Chinese and Portuguese of Portugal, chosen from the system and changeable in the window.
- **The logic of the window needs no screen:** `window` (layer, material, parameters, cuts, export, status), `viewport` (zoom and pan), `browse` (the list of files) and `lang` (the words) are plain code with their own tests; `gui` only draws them.
- **The G-code starts with the standard header:** the generator and its version, the units, the layer with its SHA-256 and the tools, and a number that is not finite is refused instead of written.
- **A rectangle with sharp corners has no repeated points:** the laser no longer stops at a corner for nothing.
- **The order of the cuts is found with a grid:** a hundred thousand openings are ordered in moments and the order is the same as before.
- **The application icon and the logos of the program:** `images/brand/` holds the icon (SVG, PNG sizes, `.ico` and `.icns`), the horizontal and vertical logos in a light and a dark version and the social preview image.
- **Shared checks updated:** the validator also compares the badge and the Version row of the README with the manifest, fails when one of its checks cannot run, and the CHANGELOG step of the workflow reads the base branch from the environment.
- **The layer is not overwritten:** `convert` refuses an output file that is the layer itself.
- **Limited reading and arc tolerance:** the layer is refused by its size before it is read into memory (the message comes in the eight languages) and `--arc-tolerance` sets how closely arcs are followed.
- **A hidden error still blocks:** `--hide` keeps a notice off the screen but an error of the reader that is hidden still counts, so the stencil of a damaged layer needs `--force`.
- **The workflows are hardened:** every action is pinned by its commit with its version in a comment, and the checkouts keep no credentials.
- **More tests:** the materials and the limits of their profiles, the reading of a layer with its size limit and its hidden notices, and the G-code and the HP-GL of the cuts.

## [0.0.3] - Openings from the Gerber viewer conversion
- **The CI builds against the tag of each sibling:** the sibling repositories are read from `depends_on` of the manifest (the ones they need in turn included) and checked out at the tag the repository is built from, so a build does not move when a sibling changes; a separate job, `Siblings at main`, builds against the main branch of every sibling to show a break before the sibling is tagged and does not hold a merge.

- **The openings come from the conversion of apertures of EH3D-GERBERVIEWER** instead of a copy of it (a dependency by path on the sibling repository): the duplicated code is gone. A polygon pad is now cut as a circle, with a note, and is refused without `--force`; before it was left out.
- **One shared helper for the command-line arguments** (`src/cli_args.rs`: flag, switch, num and a strict finish), the same file in every small utility of the suite; the copies this program had behaved the same, so nothing changes for a person.
- **Tests that run what the README and the scripts promise:** the sample of `run.sh`, `run.bat` and the README is the same command, and it is run on the files of `examples/`.
- **The banner of the README** shows the role and the technologies of this program (it showed the text of the shared library).

## [0.0.2] - A strict command line and a refusal of an incomplete stencil

- **Each dependency on a sibling repository by path says the version it needs** (`version = ">=0.0.1", path = "../EH3D-..."`), so Cargo stops at once when the sibling next to this one is older than the program expects.

- **`convert` refuses an incomplete stencil:** when the layer has pads, tracks or regions that cannot become openings (polygons, macros, regions) the file is not written unless `--force` is given.

## [0.0.1] - Solder paste stencils from the paste layer: openings, ratio checks and cutting paths

- **The openings:** the pads of the paste layer in millimetres, shrunk by the percentage of the material, with the cut line reduced by the kerf of the laser; a stencil for the bottom side can be mirrored.
- **The ratios:** the aspect ratio and the area ratio decide whether the paste leaves each opening; an opening that fails is reported and `convert` does not write unless `--force` is given.
- **The paths:** rounded rectangles, circles and obrounds in a nearest-first order, as G-code for a laser or HP-GL for a plotter, with profiles for Mylar, Kapton and steel.
- **The command line** `eh3d-stencilcam` with `convert` and `check`, and a sample paste layer.
- **13 tests** run on a computer, with damaged input.
